**指標について。** ここに載せる値は、すべての fold のテスト予測を連結して計算した値（pooled OOF）です。どの行も、その行を学習に含めていないモデルで予測しています。ホストを1台ずつ外す分割と時期のブロックで分割する場合は、テスト側の fold が単一クラスになることが多く、fold ごとの値は意味を持たないためです。

ET（表10の設定）は、ランダム分割（E1）でも macro F1 が0.65〜0.86と崩れました。これは `ccp_alpha=1e-2` で枝刈りしすぎるためで、クラス2をほとんど予測しません。このため、以下の結論には使っていません。

## 2. H1：ラベルがほぼホストで決まる → **支持（反証されなかった）**

- **E1 から E2 で macro F1 が約30〜50pt 下がりました。**
  - authors：F0 で91.3 → 51.3。最も良い条件（CB、F2）でも67.8です。
  - public15：F0 で99.7 → 50.3。最も良い条件（CB、F0）でも70.3です。
  - クラス2の F1 は、ほぼ0になります。
  - 反証の条件である「ホストを除いた特徴量でも高いまま」は満たされませんでした。
- **ランダム分割では、ホスト列を除いても（F2）性能はまったく下がりません**（authors 91.5、public15 99.7）。ほかの特徴量がホストの代わりの手がかり（代理変数）になっているためです。つまり、ホスト列を除くだけでは H1 の問題は解消しません。
- **攻撃と正常の2値 AUC は高いまま残りました**（authors の E2・F2 で97.7）。ただし、これは1台ごとの結果を並べたもので、実質的には「ホスト単位で、攻撃側のホストか正常側のホストかを順位付けできる」ことを示しています。ホストは7台・6台しかなく、ほぼすべてが単一ラベルです。役割の違うホスト（DC と端末など）のイベントの構成の違いを拾っているだけの可能性が高いです。分類の性能（F1）は崩れています。
- **ラベルが混在しているホストを外したときが決定的です。**
  - authors の CompSTA2（クラス0とクラス2）と CompSTA3（クラス0とクラス2）を外すと、どのモデル・特徴量セットでも正解率は0.5を下回り、クラス2はほぼ当たりません。
  - public15 で唯一完全に当たったのは WIN-J23N（CB、F0・F2、正解率1.000）です。しかし、時刻を除く（F1）と正解率は0.545まで下がります。この結果は H2 の項で扱います。

## 3. H2：ラベルがほぼ収集時期で決まる → **支持。ただし authors では H1 と切り分けられない**

- **ラベルと時期は、ほぼ1対1に対応しています。** E1 で時刻だけの多数決ルールが macro F1 98.9（public15）、88.4（authors）に達します。
- **public15：時刻が、ホストをまたいでラベルを決める手がかりになっています。**
  - 公開版では、どのホストの攻撃イベントも2023-12-06〜08に付け直されています。
  - 日単位のブロック（E3）で分割すると、クラス2（12-08の1日だけ）が学習データから消えます。その結果、クラス2の F1 は全条件で0です。
  - 1時間単位のブロック（E3h）では、性能はほとんど下がりません（97.9）。同じ攻撃シナリオが近い時間帯に固まっているので、1時間で区切るだけでは漏洩を防げません。
  - E2 で WIN-J23N を外したとき、時刻の特徴があれば完全に当たり、時刻を除くと崩れます。時刻のしきい値が、ホストをまたいで効いていることを直接示す結果です。
  - ランダム分割（E1）でも、時刻を除くと macro F1 が99.7 → 91.6、クラス2の F1 が99.4 → 75.4に下がります。**public15 の F0 で macro F1 がほぼ100になるのは、時刻の情報に依存しているからです。**
- **authors：時刻の列を除いても、E1 の性能はほぼ変わりません**（91.3 → 90.9）。
  - 一方、時期のブロックで分割（E3）すると67.3、時系列順の分割（E3c）では13.5（AUC 約0.55で、ほぼランダムな予測）まで下がります。
  - ただし、E3 のテスト行の90%は学習に含まれていないホストの行で、E3c は E2 の CompSTA3 の fold と同じです。**著者のデータでは、ホストと収集時期が完全に交絡しています。** H1 と H2 のどちらが性能低下の原因かは、このデータからは識別できません。
- **反証の条件**（E3 と F1 の組み合わせで高い性能が保たれる）**は満たされませんでした**（authors 61.1、public15 65.4）。

## 4. H5：重複行のためランダム分割では暗記で正解できる → **単純な形では反証。最小構成の特徴量（F4）に限れば支持**

- **E4b（同じ特徴ベクトルが学習とテストに分かれないように分割）では、F0〜F3 の性能が E1 とほぼ同じでした**（authors F0：91.2 対 91.3、public15 F1：91.5 対 91.6）。
  - 「完全に同じ行がテストにも学習にもある」ことが、高い性能の主な原因ではありません。H5 を元の形のまま述べるなら、反証されたことになります。
  - ただし、ID や分といった細かい数値だけが違う「ほぼ重複」の行は、E4b でも学習とテストの両方に残ります。ID 系を除くと（F3）、authors では91.2 → 88.5と、やや下がります。
- **E4a（重複除去）では、authors の macro F1 が91.3 → 78.2、クラス2の F1 が75.1 → 40.0に下がりました。**
  - ただし、重複を除くとクラスの構成が変わります（クラス0の割合が90%から75%に下がる）。何度も繰り返される簡単な行がなくなった分、テストが難しくなっています。
  - 「異なる事象1件あたり」の性能は、論文値よりかなり低いと言えます。
- **F4（時刻・ホスト・ID 系を除いて、イベントの内容だけを残した最小構成）が決定的です。**
  - 特徴ベクトルは84種類（authors）・89種類（public15）しかありません。そのため、E1 では、テスト行の100%が学習データにもあります。
  - 同じベクトルが学習とテストに分かれないようにすると（E4b）、macro F1 は89.2 → 49.3（authors）、88.1 → 42.5（public15）と半分近くまで下がり、クラス1の F1 はほぼ0になります。
  - **イベントの内容の特徴だけで出ている高い性能は、すべて既に見たベクトルの暗記によるものです。未知のイベントの組み合わせには汎化しません。**

## 5. まとめ

1. **論文の高い性能は、ランダム分割で、ホストと時期という「データの収集手順の跡」を学習して得られたものです。**
   - ホストを1台ずつ外すと macro F1 は約50に下がり、時系列順の分割では約14に下がります。
   - 横方向移動（ラテラルムーブメント）のクラス（クラス2）は、未知のホストや未知の期間ではほとんど検出できません。
2. **ホスト列や時刻の列を除いても解決しません。** ほかの特徴量が代理変数になるためです。また、authors ではホストと時期が交絡していて、H1 と H2 を分離できません。データの設計そのものの問題です。
3. **重複の問題は、完全な重複行よりも、特徴量の次元が小さいこと（内容の特徴ベクトルが84〜89種類しかない）にあります。** 内容の特徴だけでは、既に見たベクトルの暗記にとどまります。
4. **付随して見つかったこと：** 表10の ET 設定は、ランダム分割でもクラス2を落とします（macro F1 0.65〜0.86）。これは H9（ハイパーパラメータの不一致）の傍証になります。

## 6. 結果を読むときの注意
- E2・E3 の pooled AUC は、fold ごとに別のモデルが出したスコアを連結して計算しています。そのため、スコアの尺度の違いの影響を受けます。ET の E2・F0 での AUC が9.5になる、といった0.5を大きく下回る値は、学習したホストや時期の規則が、未知のホストや時期では逆向きに働いていることを示します。
- ホストは7台・6台しかなく、ホスト単位での標本の数は非常に少ないです。
- public15 の時刻は公開時に付け直されたものです。H2 の public15 での結論は、公開版のデータについての結論です。
