# LMD-2023 の問題点：第三者による検証の整理と仮説

- 作成日：2026-10-13
- 位置づけ：再現実験（[REPRO_REPORT.md](REPRO_REPORT.md)）の次の段階として、LMD-2023 の問題点を検証するための前提をまとめた資料です。
- 方針：第三者の主張は、私たちがすべて一次資料（GitHub 上のファイル、PDF 本文）で確認しました。そのうえで、手元のデータで確かめられるものは独自に再確認しました。

## 1. 要約

LMD-2023 に対する**査読付きの批判的検証は、まだ公開されていません**。一方で、**査読なしの第三者の分析が5件**（学生プロジェクト・修士論文・データセットカタログ）あり、互いに独立に同じ傾向を報告しています。私たちのデータ確認も、その傾向を支持しています。

| # | 仮説（問題点） | 第三者の根拠 | 私たちの確認 | 確度 |
|---|---|---|---|---|
| H1 | **ラベルがほぼホストで決まる**（ホストとラベルの交絡） | itamarit77、FocusPA、Roy | ホスト名だけで正解率97.6%（論文の行列）／98.2%（公開版） | 高 |
| H2 | **ラベルがほぼ収集時期で決まる**（時刻とラベルの交絡） | itamarit77、Roy | 公開版では時刻のしきい値2本で正解率99.998%、論文の行列では月の値だけで正解率97.2% | 高 |
| H3 | **攻撃クラスの大部分は、外部の公開データ（Splunk Attack Range）から取り込まれたもの** | FocusPA、Splunk の公開リポジトリ | 著者のリポジトリにも同じホスト・同じ日付のイベントがある。EoRS の64%は Splunk の転送エージェントのプロセス | 高 |
| H4 | **ラベルの品質が低い**（攻撃がラベル0、平常の動作がラベル1） | FocusPA | mimikatz・LaZagne・PsExec などがラベル0。実行ファイルのパスの大文字・小文字でラベルが変わる | 高 |
| H5 | **行の大量複製でランダム分割が意味をなさない** | （第三者の報告なし） | 論文の行列は95%が重複行で、テスト行の96.5%が学習データにもある。正常データの大半は4,537件のイベントを約333回複製したもの | 高 |
| H6 | **ホストや時期を分けて評価すると性能が出ない**（汎化しない） | itamarit77、FocusPA | 未検証 | 中〜高 |
| H7 | **論文の評価指標が性能を誇張・混同している** | （第三者の報告なし） | AUC は予測ラベルから計算されている。P/R/F1 はモデルごとに平均方式が違う | 高 |
| H8 | **データの版と記述が一致しない** | FETA カタログ（「前処理が不明」） | EoHT の件数が論文と25,040件違う。公開版はタイムスタンプが付け直されている | 高 |
| H9 | **論文のハイパーパラメータでは、木系モデルの結果を再現できない** | （第三者の報告なし） | 表10の設定では ET の weighted F1 が97.62（論文99.41） | 中 |

H1〜H5 は互いに関係しています。最も単純な説明は次のとおりです。

> 正常クラスは主に著者自身のノートPC（2022年6月）のログを複製したもので、EoRS クラスは主に Splunk Attack Range の公開ログ（2021〜2022年）の平常時の背景ログでできている。そのため、分類器が学習しているのは「攻撃の挙動」ではなく「どのマシンの、いつのログか」である。

### 2.2 itamarit77（授業プロジェクト）
- **主張：** `milestone2/README.md` に「LMD-2023 の benign と attack は互いに重ならない期間に収集されている。LMD の中でどう分割しても、汎化性能は測れない」とあります。
- **分割方法を変えた監査**（`milestone2/artifacts/split_audit.json`：40万行のサンプル、絶対時刻の特徴量は除外、RF）：
  - ランダム分割：AUC 1.0
  - ホスト×10分のブロックで分割：AUC 1.0
  - ホスト×日で分割：AUC 0.998
  - 時系列順の70/30分割：テスト側が100%攻撃になり、AUC を計算できない（攻撃行の約85%がテスト側に入る）
  - つまり時刻の特徴量を除いても、LMD の中だけで分割する限りはほぼ完全に分類できてしまいます。
- **別データセットへの転移**（`milestone3/results/cross_lmd_to_mordor_*.json`）：LMD で学習し、Mordor（APT29 のエミュレーションデータ）で評価しました。
  - RF：AUC 0.32〜0.42、LightGBM：AUC 0.30〜0.47、F1 は0〜0.04
  - 逆方向（Mordor で学習して LMD で評価）でも AUC 0.08〜0.67
  - ただし Mordor 側の正解ラベルは、プロセスの親子関係からたどった弱いラベルです。作者自身も「検知性能ではなく、ラベルの一貫性の確認」と注記しています。
- **ホストとクラスの偏り**（`milestone3/results/host_class_counts.json`）：下の 3.1 節で、私たちのデータでも完全に再現しました。
- **手法：** `StratifiedGroupKFold` によるホスト×時間ブロック単位のグループ交差検証と、過去の情報だけを使う35特徴量を使っています。

### 2.3 FocusPA（修士論文プロジェクト）
- **2.3M 版を、128イベントずつのウィンドウ単位で分析し、LogLLM（BERT と Llama-3-8B）を使っています。**
- **主張：**「attackrange のホストには、100%ラベル1のウィンドウがあるが、中身は Splunk 転送エージェントや DFSR の背景ログだけで、攻撃の痕跡はない」「実際の攻撃（mimikatz、ポート4444への通信、PSTools）がラベル0になっている」。
  - 誤検知とされた37件を調べたところ、36件には実際の攻撃の痕跡がありました。内訳は、他プロセスへのスレッド挿入（CreateRemoteThread）25件、RDP（mstsc）20件、PSTools 2件、mimikatz 1件です。
- **学習に含めなかったホストでの評価**（評価対象は WINDOWS10EVAL の同じ165ウィンドウ）：
  - attackrange を含めて学習：**AUC 0.498**（ランダムと同じ）
  - attackrange を除いて学習：AUC 0.662
  - 評価ホストも学習に含めた場合：AUC 0.778
- **README の結論：**「LMD-2023 で学習した検知器は、学習で見ていないマシンには汎化しない」。

### 2.4 Roy（NCI 修士論文）と dannybroyd
- **Roy：** RF の精度・F1 はいずれも1.00で、誤分類は395,020件中37件でした（p.17）。ラベルとの相関は、LAPTOP-ROPR18AK・month_6・week_25 が約−0.89、year_2021 と win-dc-128.attackrange.local が約+0.74です（p.18）。著者自身も、この結果は合成データや過学習の反映かもしれないと認めています（p.22）。
  - 以前の調査で「正常データは2023年6月」としていたのは誤りでした。図10からは**2022年6月**と読み取れます。
- **dannybroyd：** 論文と同じ9つの元特徴量を使い、層化ランダム80/20分割で検証時 F1 0.9963、テスト F1 0.9967 でした。特徴量の重要度は EventRecordID が0.183、Computer_LAPTOP が0.145 で上位です。

### 2.5 attackrange ホストの出どころ（Splunk）
- `splunk/security_content` の `data_sources/sysmon_eventid_10.yml` に、例として `win-dc-128.attackrange.local` のイベントが載っています。日時は2022-02-01、EventRecordID は150624412、内容は Rubeus.exe による winlogon へのアクセスです。
- **LMD 著者自身のリポジトリ**（`evtx_To_CSV_ExportTool/initializationFile/initializationFile.xml`、2023-04-21 にコミット）にも、**同じホストの同じ日付のイベント**（EventRecordID 150622279、DFSRs.exe）があります。私たちも手元で直接確認しました。
  - 同じホストの EventRecordID は約485,206,800付近（2022-03-10、Splunk 転送エージェント）にもあります。
  - `win-host-987.attackrange.local` のイベント（2022-03-10）も含まれています。
- `splunk/attack_data` には、同じ時期（2021-11〜2022-03）の Attack Range による横展開の記録が多数あります（T1021.003、T1021.006、T1047、T1550.003 の rubeus など）。
- これに対して、2022年論文の表2に載っているテストベッドのホストは次のとおりで、**attackrange ホストは含まれていません**。
  - Windows Server 2019 の SYSMON_SET ドメイン（`WIN-J23NIGGP1Q6.sysmon_set.local` に相当）
  - ノートPC（ユーザー名 `laptop-ropr18ak_chrsm`）

## 3. 私たちのデータ確認（独自の裏付け）

確認したデータは2つです。1つは著者の行列ファイル（`full-csv(Evaluated Titles).csv`、論文で使われたとみられる）、もう1つは公開版の生データ（1.75M「Checked」版のラベル付き CSV）です。

### 3.1 ホスト・時期とラベル（H1、H2）

公開版のホスト別のラベル件数：

| ホスト | Normal | EoRS | EoHT |
|---|--:|--:|--:|
| LAPTOP-ROPR18AK | 1,513,113 | 8 | 8 |
| WIN-J23NIGGP1Q6.sysmon_set.local | 48,786 | 2 | 26,756 |
| WINDOWS10EVAL.stefania.local | 49,710 | 355 | 3,340 |
| win-dc-128.attackrange.local | 8 | 78,988 | 395 |
| win-dc-469.attackrange.local | 0 | 60 | 0 |
| win-host-987.attackrange.local | 2 | 31,297 | 8 |

- **公開版の時刻の範囲：**
  - Normal：2022-10-10 〜 2023-12-06 19:34
  - EoRS：2023-12-06 19:33 〜 12-08 02:19
  - EoHT：2023-12-08 02:18 以降
  - しきい値2本で分類すると、正解率99.998%、macro F1 0.9999 になり、論文の最良値（ET）を上回ります。
- **論文の行列：**
  - CompSTA1（ノートPC）は Normal が1,534,397件、攻撃は13件だけです。
  - 2020年の行は全て EoRS（67,420件）、2022年6月の行は Normal が1,534,397件で攻撃は13件だけです。
  - ホスト名だけで、正解率97.64%・macro F1 0.884、月の値だけで正解率97.20%になります。これは表10の設定の ET（正解率97.85%）と同じ水準です。

### 3.2 攻撃クラスの中身とラベルの品質（H3、H4）
- **EoRS（110,710件）の中身：** 64.1%が Splunk 転送エージェントのプロセス（splunk-winevtlog.exe など）、28.7%がプロセス名（Image）が空の行、残り7.2%がそれ以外です。99%以上は attackrange ホストの行です。
- **既知の攻撃ツールのラベル：**

  | 痕跡 | Normal | EoRS | EoHT |
  |---|--:|--:|--:|
  | mimikatz | **51** | 0 | 88 |
  | LaZagne | **108** | 0 | 0 |
  | PsExec | **109** | 61 | 0 |
  | WannaCry（wcry、wnry、tasksche） | **6** | 0 | 0 |
  | ポート4444への通信 | **120** | 0 | 1 |

- **パスの大文字・小文字でラベルが変わります：**

  | プロセス | Normal | EoRS | EoHT |
  |---|--:|--:|--:|
  | `C:\Windows\System32\lsass.exe` | 0 | 424 | 14,384 |
  | `C:\Windows\system32\lsass.exe` | 7,984 | 480 | 0 |
  | `C:\Windows\System32\svchost.exe` | 0 | 862 | 15,574 |
  | `C:\Windows\system32\svchost.exe` | 4,535 | 223 | 0 |

  公開されているラベル付けルール（ETCExp の `labelling.py` と `RBPolicy`）は、プロセス名やコマンドラインの**完全一致**で判定します。そのルールには `C:\Windows\System32\svchost.exe` や `lsass.exe` が EoHT として入っています。
- **公開ルールを再適用した結果：** 公開版のラベルと比べると、EoHT は30,507件中30,094件が一致しました。一方、**EoRS は110,710件中わずか370件しか一致せず**、109,054件はルール上 Normal になります。EoRS のラベルは、公開ルールではなく、別の方法（ホスト単位の割り当てとみられる）で付けられた可能性が高いです。

### 3.3 複製と前処理（H5、H8）
- **公開版：** LAPTOP-ROPR18AK の約151万行は、**EventRecordID が4,537種類しかありません**。1件あたり330〜346回、時刻だけを変えて複製されています（約75分間隔）。
- **公開版の時刻：** UtcTime 列は表計算ソフトで壊れていて（例：「30:32.4」）、元の時刻を復元できません。SystemTime は2022-10〜2023-12 に分布しています。著者の初期化ファイルやテストベッドの記録では2021-12〜2022-06なので、**時刻が付け直された**ことになります。
- **論文の行列：**
  - 1,777,930行のうち1,688,635行（95.0%）が完全な重複で、異なる行は89,295種類しかありません。
  - ランダムに75/25分割すると、**テスト行の96.5%は、全く同じ行が学習データにもあります**。
  - ラベル0・1・2の順に連続したブロックで並んでいて、MinMax 変換をファイルごとに別々に行った跡があります（例：日付の列の値が42種類あり、本来の最大31種類を超える）。
  - EoHT が55,547件で、論文の30,507件と一致しません。

### 3.4 評価と報告（H7、H9）：再現実験から
詳細は [REPRO_REPORT.md](REPRO_REPORT.md) を参照してください。
- 論文の AUC は、**予測ラベルから**計算したものと一致します。予測確率から計算した AUC は、全モデルで99.5以上になります。
- Precision / Recall / F1 は、LR・NB では weighted 平均と、SGDC・LinearSVC では macro 平均と一致します。表11の中で平均方式が混在しているとみられます。
- 表10の設定の ET は weighted F1 97.62 で、論文の99.41を再現できません。枝刈り（`ccp_alpha`）を外すと99.04まで近づきます。

## 4. 仮説ごとの詳細と、検証の方法

| 仮説 | 内容 | 反証の条件 | 検証実験（案） |
|---|---|---|---|
| H1 ホストの交絡 | 分類器は主にホストの識別で性能を出している | ホストの特徴量を除いても、学習に含めなかったホストで高い性能が出れば反証 | (a) ホストに関する特徴量（Computer、EventRecordID、ProcessId など）を外す実験、(b) ホストを1台ずつ外して評価する、(c) ホスト名だけで分類するベースラインと比べる |
| H2 時刻の交絡 | 収集時期の違いでラベルが決まっている | 時刻の特徴量を外し、時期をまたいで分割しても性能が出れば反証 | (a) 時刻の7特徴量を外す実験、(b) 時刻順に分割、(c) 時刻のしきい値だけのベースラインと比べる |
| H3 外部データの混入 | EoRS の大部分は Splunk Attack Range の公開ログで、背景ログが攻撃として扱われている | attackrange の行に、論文が書く攻撃（EternalBlue など）の痕跡が十分あれば反証 | (a) `splunk/attack_data` の該当ログ（Git LFS で保存）と、EventRecordID・時刻・内容で突き合わせる、(b) attackrange ホストを除いたときの性能を見る |
| H4 ラベルの誤り | 攻撃がラベル0、平常の動作がラベル1になっている | — | (a) 攻撃ツールの痕跡やプロセスの親子関係に基づいて独自に付け直したラベルと比較する、(b) ラベル誤り率を推定し、性能指標への影響を測る |
| H5 複製による楽観的な評価 | ランダム分割では、学習データの暗記で高い性能が出る | 重複を除いても、同じ性能が出れば反証 | 重複除去後のデータ、または同じイベントの複製が学習とテストに分かれない分割で、もう一度評価する |
| H6 汎化しない | 新しいホスト・時期・環境では検知できない | — | ホストを外した評価、時期をまたぐ評価、別データセット（Mordor、EVTX-ATTACK-SAMPLES、LMDG）への転移 |
| H7 指標の問題 | 予測ラベルからの AUC と平均方式の混在で、比較が歪んでいる | — | 予測確率からの AUC・macro F1・クラス別 F1 で、全モデルを評価し直す（再現実験で一部実施済み） |
| H8 データ版の不整合 | 論文のデータと公開データが一致しない | — | 版ごとの差分表を作る（1.75M・1.87M・2.3M、著者の行列ファイル） |
| H9 ハイパーパラメータの不一致 | 表10は実際に使われた設定と異なる | — | 感度分析（ccp_alpha・max_depth など）を広げる |

**優先順位の提案：**
1. H1・H2・H5 を、特徴量の除外と分割方法の変更で定量化する。手元のデータですぐ実行できます。
2. H4 は、ラベルを付け直して影響を測る。
3. H3 は、Splunk のログと突き合わせる（大容量ファイルのダウンロードが必要です）。
4. H6 は、別データセットへの転移で確かめる。

## 5. 限界と注意点
- 第三者の分析は、どれも**査読されていません**（授業プロジェクト・修士論文・個人リポジトリ）。また、いずれも公開版の「Checked」版（2024-03 以降）を使っていて、論文で使われたデータそのものではありません。
- 一方で、私たちは**論文で使われたとみられる著者の行列ファイル**でも、ホストと時期の交絡（3.1節）と重複（3.3節）を確認しました。そのため H1・H2・H5 は、論文の結果そのものに当てはまると考えられます。
- H3（Splunk 由来）は、ホスト名・日付・EventRecordID の系列が一致することに基づく推論です。ログの中身同士はまだ突き合わせていません。
- ここでは問題を「データの作り方と評価方法」の水準で扱い、意図については何も判断しません。
- itamarit77 の別データセットへの転移で使われた Mordor のラベルは、作者自身が「弱いラベル」と注記しています。数値は参考程度に扱うべきです。
